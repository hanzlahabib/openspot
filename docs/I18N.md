# Localization

Status: **infrastructure only** (roadmap U-02, partial). The machinery below works and is tested,
but only the mode bar and the Preferences window go through it today. Everything else is still
English literals, and only one language (en-US) ships. A pseudo-locale exists to make unmigrated
text easy to spot.

## How it works

- Crate `crates/openspot-i18n`, built on [Project Fluent](https://projectfluent.org/)
  (`fluent-bundle`, `unic-langid`) and `sys-locale` for reading the OS language.
- Translations are `.ftl` files in `crates/openspot-i18n/locales/`, compiled into the binary with
  `include_str!`. **`en-US.ftl` is the source of truth**: every key used in code must exist there,
  and it is the fallback for any key a translation lacks.
- The active language is process-wide. Call `tr("key")` anywhere; there is no handle to pass.
- The choice is stored in the preferences file as `language` (a BCP 47 tag such as `"de-DE"`, or
  absent to follow the operating system) and changed in Preferences > Appearance > Language.
  Changes apply immediately.
- Selection order at startup: stored preference, then OS locale, then en-US. A tag is matched
  exactly, then by language (`de-AT` gets `de-DE` if that is the shipped German), then en-US.

## API

```rust
use openspot_i18n::{Args, tr, tr_args};

ui.button(tr("mode-preferences"));

let mut args = Args::new();
args.set("count", n);                  // numbers select plural forms
ui.label(tr_args("survey-points", &args));
```

Plurals use Fluent selectors, so each language states its own CLDR categories:

```ftl
survey-points = { $count ->
    [one] { $count } measurement point
   *[other] { $count } measurement points
}
```

`tr` returns `String`, which egui accepts as widget text.

### When a key cannot be resolved

| Situation | Debug build | Release build |
|---|---|---|
| Key missing in the active language, present in en-US | en-US text prefixed with `[en] ` | en-US text |
| Key missing everywhere | `[missing:the-key]` | the bare key |

The prefix and brackets are deliberately ugly so they are noticed in development. The lint test
below stops a missing key from reaching a release in the first place.

## Pseudo-locale

`xx-PSEUDO` has no file. It renders every en-US message accented, padded by about 30 % and
wrapped in brackets: `Survey` becomes `[Súrvéy~]`. On screen:

- text **without** brackets was not migrated to `tr` (or comes from a type's `label()` method
  that is still a literal);
- text that overflows, truncates or wraps badly will do the same in German or Finnish.

It is listed in the language selector in debug builds only. To use it in a release build, set
`"language": "xx-PSEUDO"` in the preferences file.

## Migrating a file to `tr`

1. Add `openspot-i18n.workspace = true` to the crate's `Cargo.toml` if it is not there.
2. For each user-visible literal, pick a key and add it to `en-US.ftl`. Keys are kebab-case,
   prefixed by area: `prefs-...`, `mode-...`, `survey-...`. One message per sentence; do not
   build sentences by concatenating translated pieces.
3. Replace the literal with `tr("key")`. Keys **must be string literals**, because the lint
   test cannot see keys assembled at run time. For an enum label, `match` to a literal per variant.
4. Replace `format!("... {x} ...")` with a message using `{ $x }` and `tr_args`. Counts become a
   plural selector.
5. Do not use the text as an identity. egui derives widget IDs from titles and labels, so a
   window whose title is translated needs an explicit `.id(...)` (the Preferences window has one),
   otherwise it jumps position when the language changes.
6. Run `cargo test -p openspot-i18n`. Switch to `xx-PSEUDO` and click through the screen.

Not translated on purpose: file extensions, units written as symbols, product names, protocol
names (`SSID`, `BSSID`, `iperf3`), and log text meant for bug reports.

## Adding a language

1. Copy `locales/en-US.ftl` to `locales/<tag>.ftl` (for example `de-DE.ftl`).
2. Set `language-name` to the language's own name ("Deutsch (Deutschland)"). It labels the entry
   in the selector.
3. Translate values. Keep keys and variable names (`{ $count }`) unchanged. Untranslated keys
   may be deleted from the file; they fall back to English.
4. Register the file in `EMBEDDED` in `src/catalog.rs`:
   `("de-DE", include_str!("../locales/de-DE.ftl"))`.
5. `cargo test -p openspot-i18n` checks that the file parses, has no duplicate ids, names itself,
   and defines no key that en-US lacks.

Translations are original text written for OpenSpot. Do not copy wording from other products
(see [CLEAN_ROOM.md](CLEAN_ROOM.md)).

## Tests

| Test | What it guards |
|---|---|
| `tests/catalog.rs` | lookup, arguments, English and German plurals, fallback to en-US, missing key, pseudo-locale |
| `tests/shipped.rs` | embedded files parse, no duplicate ids, every locale has `language-name`, no extra keys, locale switching |
| `tests/lint.rs` | every literal `tr("key")` / `tr_args("key", ..)` in `crates/*/src` exists in `en-US.ftl` |
| `src/locale.rs` | BCP 47 and POSIX (`de_DE.UTF-8`) parsing, negotiation |

## Known gaps

- Only en-US ships; no translation has been reviewed by a native speaker.
- Right-to-left layout is not handled. Fluent's directional isolation marks are switched off
  because egui's bundled fonts cannot draw them; revisit when RTL is in scope.
- egui's default fonts cover Latin scripts only. CJK, Arabic or Indic languages need a font to be
  bundled and registered first.
- Dates and numbers are not locale-formatted.
- Exported reports and CSV headers are not localized.
